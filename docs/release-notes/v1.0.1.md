# ReVibe 1.0.1

A small release for fresh Vibe profiles: the Models page could not register a
Mistral model, so a new install offered only Vibe's single built-in model and
never showed the ones you use.

**Downloads**

- `ReVibe-1.0.1-x86_64.AppImage`: Linux. `chmod +x` it and run it.
- `ReVibe-1.0.1-setup.exe`: Windows installer.
- `ReVibe-1.0.1-portable.exe`: Windows, a single file with nothing installed.

You need the Vibe CLI: `uv tool install mistral-vibe`, then `vibe --setup`. The
Windows builds are not code-signed, so SmartScreen asks before the first launch.

**Fixed**

- Settings → Models allows adding and removing models on the built-in Mistral
  card. Vibe keeps its models in `~/.vibe/config.toml`, and a fresh profile has
  none, so the card had nothing to show and no way to add anything. Load models
  now reads the Mistral catalog and writes the `name`, `provider` and `alias`
  entries Vibe accepts; the picker picks them up without a restart.
- The model picker says where models come from when only one is registered, and
  points to Settings → Models.

**Notes**

- Models written without a `provider` are dropped by Vibe 3.0.4, so older
  alias-only entries stop appearing. Re-add them from the Models page.
- Nothing changed for sessions, providers already configured, or the Kodlo
  build.
