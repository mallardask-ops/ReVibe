# ReVibe 1.0.2

A Windows release: the app now finds the Vibe CLI and the key it saved when
Windows blocks the system keyring, and it reads Vibe's own files as UTF-8.

**Downloads**

- `ReVibe-1.0.2-x86_64.AppImage`: Linux. `chmod +x` it and run it.
- `ReVibe-1.0.2-setup.exe`: Windows installer.
- `ReVibe-1.0.2-portable.exe`: Windows, a single file with nothing installed.

You need the Vibe CLI: `uv tool install mistral-vibe`, then `vibe --setup`. The
Windows builds are not code-signed, so SmartScreen asks before the first launch.

**Fixed**

- **The Vibe account and key.** `vibe --setup` saves the key in the OS keyring,
  and falls back to `$VIBE_HOME/.env` when the keyring is unavailable, which is
  common on Windows. ReVibe read only the keyring; it now reads that file too,
  and Settings shows the source as `Vibe CLI (~/.vibe/.env)`.
- **The Windows keyring backend.** The packaged sidecar now ships keyring's
  metadata and the `win32ctypes` modules it needs for Windows Credential
  Manager. Without them a key saved by the CLI was invisible to the app.
- **Finding Vibe.** Launchers start the app without your shell PATH, and the
  fallback paths were Linux only. The sidecar now looks in the places `uv tool`
  and `pipx` install to on Windows (`%APPDATA%\uv\tools\…\Scripts`, pipx venvs)
  before asking PATH, which is also where the model list and version come from.
- **Vibe's version.** Windows keeps packages under `Lib\site-packages`, not
  `lib/python*/site-packages`, so the installed version showed as unknown.
- **Models of other providers.** The provider worker's MCP server is registered
  with Vibe's own `python.exe` instead of the packaged sidecar, which cannot run
  it. This affected subagents on every platform.
- **Text encoding.** Config, instructions, agents and usage files are read and
  written as UTF-8 with LF; a Cyrillic name in `config.toml` or `AGENTS.md` no
  longer fails with a decoding error on Windows.

**Notes**

- Models written without a `provider` are dropped by Vibe 3.0.4, so older
  alias-only entries stop appearing. Re-add them from Settings → Models.
- Nothing changed for the Kodlo build.
